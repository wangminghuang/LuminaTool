# 长 Markdown 导出空白 PDF：分析、修复与复用

本文记录本项目“几十页 PDF 导出后全为空白”的排查证据、修复原理、实现中遇到的坑，以及在另一台电脑或另一个项目中复用核心代码的方法。可复用实现位于 [`app/lib/pdf-export-core/`](../app/lib/pdf-export-core/)；核心接入和依赖步骤也在本文中。

## 故障结论

源 Markdown 和预览克隆均有内容；问题出在导出库把整篇长文先绘制到一张超高 canvas 上。浏览器创建了 canvas 尺寸，但该尺寸超过当前环境的可用单边限制，结果 canvas 是透明的。随后 PDF 库仍按页切割并保存这张透明图，所以生成文件页数正常，却整页空白。

当前页面没有独立的 `.md` 文件读取控件；导出摘要取自 Markdown 编辑器的当前内容。因此如果其他版本增加文件导入，文件读取结果仍应先进入编辑器状态，再把当前 Markdown 传入核心。

附件诊断记录的关键数值：

| 阶段 | 观测值 | 含义 |
| --- | ---: | --- |
| Markdown 输入 | 51,285 字符、104,707 UTF-8 字节、2,406 行 | 内容已进入编辑器；没有 NUL 或替换字符异常 |
| Markdown 渲染结果 | 204,768 个 HTML 字符 | Markdown 解析没有退化为空内容 |
| 编辑器预览元素 | 941 × 41,855 CSS px | 预览 DOM 很长，但有实际布局 |
| PDF 克隆容器 | 703 × 46,335 CSS px | 克隆时缩窄到打印宽度，内容重新换行并增加高度 |
| 原先整篇 canvas | 1,406 × 92,670 px，约 45 页 | 高度超过该环境可用 canvas 单边尺寸 |
| 像素抽样 | 7 个区域的透明比例都是 1，可见非白像素比例都是 0 | canvas 本身没有画出内容 |

该 canvas 像素面积约 1.30 亿，低于项目日志里设置的面积告警值，但它的**高度**已经达到 92,670 px。只检查总像素面积不够；canvas 单边限制也必须考虑。浏览器和设备的限制会变化，代码里的 32,767/65,535 px 数值只是风险参考，不应当用来证明更小的整篇 canvas 一定可靠。

原日志还显示预估克隆高度是 31,269 px，真实克隆高度是 46,335 px。预估只是按宽度比例做线性计算，无法正确预测窄版面中的换行、复杂块元素高度和避分页插入的留白；更窄的宽度可能让文档变高。应以导出容器的实际尺寸为准，不能把这个估算作为页数或画布尺寸的依据。

## 排查时容易误判的地方

### “有内容像素占比”曾经把透明区域当成内容

最初的采样逻辑把 alpha 小于 250 也当作非白内容。纯透明像素 alpha 为 0，因此整片空白区域会被计成“有内容”。当前实现忽略几乎全透明像素，将半透明 RGB 与白底合成后再统计可见非白像素，并另外报告透明占比。这样才能区分透明空画布、白底空白页和真实文字/图形。

### 预览高度不是 PDF 克隆高度

预览区宽度是 941 px，PDF 克隆宽度约 703 px。克隆后浏览器会重新排版，表格、长代码、列表、公式和 `break-inside: avoid` 都可能改变高度。预览的 `scrollHeight` 只能用于粗略观察，克隆后的容器尺寸才是分页和裁切依据。

### 避免分页会插入不可见的留白块

`html2pdf.js` 的 CSS 分页插件会检查 `break-inside: avoid` 和配置中的 `avoid` 选择器，并在元素前插入普通 `<div>` 留白。它们不一定有 `.html2pdf__page-break` 类名；只数显式分页标记会漏掉这些空白。诊断应同时看克隆后的总高度、元素尺寸和分页规则。

### 一个“能生成”的 PDF 不代表绘制成功

canvas 尺寸可能有效、`getImageData` 也可能成功，PDF 文件也能正常保存；这些都不能证明像素有内容。要检查采样像素的 alpha/可见颜色，或者逐页抽样。

### 缩小 `scale` 不能作为完整修复

降低缩放比例会减小 canvas 像素尺寸，但仍会尝试绘制整篇文档。文档继续变长、浏览器变化或面积限制收紧后问题会重新出现，也可能牺牲输出清晰度。逐页渲染直接限制每张 canvas 的高度，才是长文档的主要修复。

## 当前修复的工作流程

核心实现在 [`app/lib/pdf-export-core/index.ts`](../app/lib/pdf-export-core/index.ts)，页面只负责传入预览 DOM、Markdown 摘要、设置，并显示诊断下载按钮。

1. 等待字体就绪，并临时缩小超宽 KaTeX 行间公式；导出结束后恢复原样。
2. 调用 `html2pdf.js` 的 `toContainer()`，保留它的打印宽度克隆和 CSS/legacy 避分页处理。**不调用 `toCanvas()`**，因此不会创建整篇的 canvas。
3. 从克隆容器读取实际宽、高和链接位置。分页高度按打印区域和 html2pdf 分页插件相同的 CSS 像素取整方式计算。
4. 对每一页调用 `html2canvas`，只裁切当前页的 `x/y/width/height` 区域。A4、缩放 2 时，每张页面 canvas 大约是 1,406 × 2,063 px，而不是 1,406 × 92,670 px。
5. 将每张页面 canvas 作为 JPEG 写入 `jsPDF`，逐页添加 PDF 页面；对文本链接逐页添加链接区域。写入后立即把 canvas 宽高设为 0，减少多页位图同时占用的内存。
6. 完成后保存 PDF，并自动下载结构化诊断 TXT。诊断不包含 Markdown 正文；导出后页面也保留“下载诊断 TXT”按钮，以便浏览器拦截自动下载时手动取回。

原先导出的 PDF 本身也是整页位图，因此新流程延续了该输出形式。分页后每页仍是清晰度为 scale 2 的图像页；长文档不会占用一张超高画布。

## 依赖与跨电脑复用

当前项目使用 pnpm，并把 html2canvas 和 jsPDF 作为**直接依赖**，版本与现有 html2pdf.js 依赖相匹配：

```json
{
  "html2canvas": "1.4.1",
  "html2pdf.js": "^0.14.0",
  "jspdf": "4.2.1"
}
```

这是有意的依赖配置：`pdf-export-core` 的源码直接导入 `html2canvas` 和 `jspdf`。pnpm 使用严格的依赖链接；仅因为 `html2pdf.js` 间接依赖它们，并不保证应用源码可以直接导入这些包。另一台电脑从仓库获取代码后，在项目根目录安装锁文件中记录的依赖：

```bash
pnpm install --frozen-lockfile
```

维护依赖时优先使用 `pnpm add` 更新 `package.json` 和锁文件，不要手改 `node_modules`。如果某个包已存在于本机 pnpm 内容缓存，且只需按锁文件重新建立本地链接，可运行 `pnpm install --offline --ignore-scripts --frozen-lockfile`；这台机器上的直接依赖就是用这种方式链接的。其他机器没有相同缓存时，不要加 `--offline`。

如果把核心复制到另一个项目，则从项目根目录添加这三个直接依赖：

```bash
pnpm add html2canvas@1.4.1 html2pdf.js@0.14.0 jspdf@4.2.1
```

提交并带上更新后的 `package.json` 和 `pnpm-lock.yaml`。在另一台机器上不要只复制 `node_modules`；使用锁文件重装才能复现依赖版本。本文编写过程中只做过离线依赖链接更新，没有运行构建或测试。

当前应用保留 [`app/types/html2pdf.d.ts`](../app/types/html2pdf.d.ts) 作为应用范围的类型增强。为便于单独复制，核心目录在内部定义了所需的 worker 形状并对分页选项做类型适配，不依赖这份全局声明。核心 `index.ts` 的输入设置类型是 `PdfExportSettings`；Markdown 渲染和预览 CSS 由宿主应用提供。

## 在新项目接入前检查

- 只在浏览器中调用导出函数；传入的 DOM 必须已挂载，并完成最终样式布局。
- 确认打印克隆根元素能够携带需要的 CSS。KaTeX 内容需要加载 KaTeX 样式；自定义主题若依赖祖先选择器，要保证克隆根也有对应类或 CSS。
- 远程图片需要允许 CORS，否则相应图片可能不显示或污染 canvas；检查诊断里的图片加载状态。
- 保留 `html2pdf.js` 的 `toContainer()` 分页处理，但不要再在这套流程中调用它的整篇 `toCanvas()`。
- 如果更改纸张、页边距或缩放，继续使用实际克隆宽度、打印区域比例和页面 CSS 高度重新计算页片尺寸。
- html2pdf 的 CSS 分页高度按整数 CSS px 取整，而画布页高按宽高比计算，两者可能相差不到 1 CSS px。本实现按分页边界移动裁切窗口、按画布宽高比决定画布高度；页边界会有约 1 个输出像素的重叠，用来避免因取整产生漏白缝。
- 每页独立调用 html2canvas 会重复克隆/遍历 DOM，长文档比一次光栅化多一些 CPU 时间；换来的是每次只分配一张页面大小的 canvas。诊断文件会记录每页的绘制耗时，便于检查具体设备的速度。
- 不要仅凭 PDF 页数、canvas 的 `width/height` 属性或日志警告判断结果；抽样确认每页有可见像素。
